How a CAN bus decides who talks

When several ECUs transmit at once, CAN settles it bit by bit: a 0 is dominant and overwrites a 1, so the lowest ID wins and nothing is corrupted. Next to it, the J1939 encoding from my CAN-Net project, live.

Projects

What I've built

CAN-Net: embedded networking and a J1939 stack

A from-scratch vehicle networking stack, from transport basics to an RTOS on the bus. View the repo

  • SocketCAN with kernel-level ID filtering, DBC encoding and decoding with cantools, and documented bus contention between three nodes.
  • J1939 by hand: 29-bit IDs, real SPNs (engine and vehicle speed), BAM multi-packet transport and request/response diagnostics, stress-tested with 3 interleaving ECUs.
  • Zephyr RTOS bridged to Linux CAN: its CAN task's frames matched byte for byte on the shared bus, with preemption verified.
  • 360-trial benchmark, 35 unit tests and GitHub Actions CI.
PythonCSocketCANpython-cancantoolsJ1939ZephyrGitHub Actions

ControlLoop-RT: real-time firmware

The embedded side of my controls project. View the repo

  • A 1 kHz Zephyr task in C driven by a timer interrupt, with priority preemption verified.
  • Watchdog, dual-sensor voting (200 of 200 faulty samples caught) and an active-hold safe state.
CZephyr RTOSWatchdogISO 26262 (documented)

TelemOps: CAN telemetry pipeline

From CAN frames to live dashboards. View the repo

  • DBC-encoded signals over SocketCAN, decoded and batched into Postgres, shown in Grafana with alerts.
  • Zero loss up to 5,195 frames/s; the ceiling traced to the ingestor's receive loop. Docker, Kubernetes and Terraform.
PythonSocketCANPostgresGrafanaKubernetesTerraform
